# Phase 2 提案: 電話自動応答 + テキスト化

## 現状の課題

- 月50件の電話問い合わせのうち、営業時間外の取りこぼしが発生している
- 電話の内容がSlackに記録されないため、メール・LINEの問い合わせと違って
  対応履歴が一元化されておらず、担当者の記憶や個人メモに依存している
- 現行システム(MVP)はメール・LINEのみが対象で、問い合わせ全体(メール200件/
  LINE500件/電話50件、合計750件/月)のうち電話分だけが自動化の恩恵を受けていない

## 提案内容

1. Twilioで050番号を取得し、既存の代表電話番号から転送設定を行う
2. 着信をTwilioで音声録音し、音声認識(Whisper等)でテキスト化する
3. テキスト化した内容を、既存の`classify-and-notify`にそのまま合流させる
   (`source_channel: "phone"`を追加するだけで、AI分類・Slack通知・緊急LINE通知の
   仕組みをそのまま再利用できる)
4. 営業時間外の着信は、テキスト化後にSlackへ「営業時間外の着信」ラベル付きで通知し、
   翌営業日の対応漏れを防ぐ

## 期待される効果

- 電話の取りこぼし: 現状推定15%程度 → ほぼ0%(録音+テキスト化により内容が必ず残る)
- 問い合わせ対応の一元化: メール・LINE・電話すべてがSlackの`#物件連絡`に集約される
- クレーム性の高い電話も、既存の緊急通知ロジックでLINEグループに即時通知される

## 技術的な位置づけ

既存システムの`messages`テーブル・`classify-and-notify`関数はチャネルを問わない
設計になっているため、Phase 2は**新しいシステムを作るのではなく、入力チャネルを
1つ追加するだけ**で実現できる。既存のAI分類ロジック・通知ロジック・冪等性の
仕組みをそのまま再利用できるため、Phase 1(MVP)への追加投資として費用対効果が高い。

## 費用

- 初期費用: 12万円(税込)
- 月額追加費用: 5,000円程度(Twilio番号維持費+通話料+音声認識API利用料)
- 開発期間: 3営業日

## 進め方

要件確定後、まずTwilioの050番号取得と着信転送設定から着手し、テスト着信での
音声認識精度を確認した上で、既存の`classify-and-notify`との連携部分を実装する
想定です。
